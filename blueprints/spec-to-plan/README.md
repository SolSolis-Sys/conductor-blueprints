# Spec → Implementation Plan

**Cost tier:** medium (~$0.10/run)  
**Best for:** Converting technical specifications into phased, agent-assigned implementation plans with atomic tickets.

## What it does

Transforms a structured technical specification (roadmap, ADRs, API definitions) into a detailed implementation plan. Outputs a PLAN-*.md file with:

- Phased breakdown (v0.X, v0.Y, etc.)
- Atomic tickets (8-15 per phase) with DONE-WHEN criteria
- Dependency ordering (critical path)
- Agent assignment (matos/janus/theia)
- Token cost estimates per ticket

Hybrid workflow: deterministic spec extraction (TOOL-like) + LLM analysis (planning, decomposition) + plan assembly.

## Inputs

| Name | Required | Default | Type | Description |
|------|----------|---------|------|-------------|
| `spec_path` | ✅ | — | string | Absolute path to spec markdown file (e.g., `/specs/conductor-memory.md`) |
| `project` | ✅ | — | string | Project name (e.g., `conductor-memory`, used in output filename) |
| `output_path` | ✅ | — | string | Absolute path where PLAN-*.md will be written (e.g., `/plans/PLAN-conductor-memory-v0.2.0.md`) |
| `focus_version` | — | `v0.2.0` | string | First version to detail (subsequent versions summarized) |

## Example

```bash
conductor run solfoundy/spec-to-plan \
  --spec_path "/path/to/specs/conductor-memory.md" \
  --project "conductor-memory" \
  --output_path "/path/to/plans/PLAN-conductor-memory-v0.2.0.md" \
  --focus_version "v0.2.0"
```

## Agent flow

```
spec-reader (extract)
    ↓ (versions, ADRs, gaps)
phase-analyzer (decompose)
    ↓ (phases, dependencies, complexity)
task-decomposer (ticket breakdown)
    ↓ (8-15 atomic tickets)
plan-writer (assemble & write)
    ↓
PLAN-*.md (ready for dispatch)
```

## Conventions
- Agent assignment: matos (Python/backend), janus (frontend), theia (specs)

## Spec file format

Expected spec markdown structure:

```markdown
## Roadmap

| Version | Feature | Status |
|---------|---------|--------|
| v0.2.0 | ... | planned |

## ADRs

| ADR-ID | Decision | Status |
|--------|----------|--------|
| ADR-01 | Use PostgreSQL for ... | accepted |

## API Functions

```
funcName(arg: Type) → ReturnType
```

## Context Levels

| Level | Description |
|-------|-------------|
| user | ... |

## Known Gaps

- Gap 1
- Gap 2
```

## Common issues

- **Spec not found**: Ensure `spec_path` is absolute and file exists
- **No tickets generated**: Check spec has versions and ADRs defined
- **High cost**: Reduce focus to smaller version or fewer phases
- **Missing dependencies**: Verify ADR table is present in spec with `Status: accepted`

## Requirements

- conductor v0.1.7+
- Spec file in markdown with roadmap/ADR tables
- Write permissions on target directory
